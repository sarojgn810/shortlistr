# Known-good versions — a lock, not a requirement.
#
# requirements.txt keeps `>=` floors on purpose: this repo is public, people
# clone it onto whatever Python they have, and hard pins there would be
# hostile. But "whatever resolves today" is not reproducible either, and the
# engine tag the platform pins guarantees the *code* while saying nothing about
# the dependencies it runs on — so that guarantee was only half true.
#
# This file closes the other half. CI and the container install with
#   pip install -r automation/requirements.txt -c automation/constraints.txt
# and get the exact set the suite passes on. Someone cloning the repo still
# gets the floors and a fresh resolve.
#
# Produced by resolving requirements.txt into an empty virtualenv and freezing
# the result — not by freezing a working machine, which captures unrelated
# packages and pins that cannot co-exist. That mistake produced a
# ResolutionImpossible on the first attempt at this file.
#
# Regenerate deliberately: fresh venv, install, run the suite, then capture. A
# constraints file updated because something broke has stopped constraining.
